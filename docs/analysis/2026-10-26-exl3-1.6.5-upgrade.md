## Behavior changes reaching the managed runtime

No Tabby change is needed; Tabby's generator arguments are unchanged and 1.6.5 only adds parameters.

- Fair prefill/decode scheduling is on by default (`prefill_cooldown=4`).
- Quantized-KV prefill staging is capped by `EXL3_QC_STAGING_PAGES` (default 256).
- Batched speculative readback is on; `EXL3_NO_BATCH_READBACK=1` restores the serial path. Upstream measured +4–5% decode on a 27B MTP workload; not measured here.
- Sparse-head drafting and `draft_max_rows` default off, and Tabby does not expose them.

## Disk cache after the upgrade

The fingerprint includes the EXL3 version, so the two 1.6.3 folders (49.4 GiB of the 50 GiB root) could never be read by 1.6.5. Switching Flash Next 4.00bpw hq2 ↔ 3.50bpw Q8 loaded without stalls, but each new 1.6.5 folder was held to ~0.1–0.3 GB and a switch back reused 0 tokens of the 65.6k prompt:

- `_reclaim_root` removes stale sibling folders at open only until the new folder's current size, zero for a new folder, fits.
- `_make_room` then evicts the folder's own pages first; `_reclaim_siblings` frees sibling pages only when the folder has nothing of its own left, a margin at a time.

After moving the 1.6.3 folders to `D:\AI\exl3-disk-cache-stale-1.6.3` (delete it once a warm 1.6.3 rollback is no longer wanted), each switch back restored 65,536 of 65,578 prompt tokens from disk: first token ~3 s against ~28 s cold. `npm run exl3:promote-wheel` now removes other-version folders on every promotion.
