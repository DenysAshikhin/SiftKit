# Memory vault mockup

The Memory tab redesigned as a custom vault: notes, `[[wikilinks]]`, backlinks, tags, graph and per-note history. It replaces the triple-graph memory inspector.

Open `index.html` directly in a browser. There is no server, build step or network access. Nothing you do is saved.

## What works

- **Opens on the graph.** Click a node to preview it in the right pane; double-click to open it. The right pane shows each note's local graph by default.
- **Notes read like notes.** Each note starts with a short lead paragraph, then compact `**Label** [[a]] · [[b]]` rows rendered as link pills. Plans and goals become checklists. Long tails and unverified facts fold into callouts. Notes for things that are mostly linked to get a "where it shows up" card.
- **Daily notes**: a one-line summary, a thumbnail grid of the day's captures, and what was learned that day.
- **File tree**: starred notes, then folders by type with icons. The 2.5k link-only notes are hidden unless toggled on.
- **Read / Edit** (Ctrl+E). The editor has `[[` autocomplete. Saving creates a `you` revision.
- **Wikilinks**: hover to preview, click to follow, Ctrl+click to open in a new tab. Clicking an unresolved link creates that note.
- **Rename**: click the note title. Every inbound link is rewritten in one step and the old title is kept as an alias.
- **Right pane**: linked and unlinked mentions, outgoing links, outline, local graph (depth 1–2), history, vault stats.
- **History**: per-note revisions (migration, note-writer, tidy pass, you) with a line diff and *Restore this version*.
- **Graph view** (Ctrl+G): custom canvas force layout. Includes folder filters, minimum-links slider, highlight search, drag, pan and zoom.
- **Review** (✓ in the ribbon): every `#unverified` fact migrated from the old candidate queue, with confirm/drop buttons.
- **Search** with `tag:#x`, `path:Folder` and `type:x` filters, and a quick switcher (Ctrl+O / Ctrl+K).
- **Status bar**: note-writer queue, tidy-pass progress, and *Export as .md*.

URL shortcuts: `?view=graph`, `?view=review`, `?note=SiftKit&right=history&rev=1`.

## Data

`vault-data.js` is generated by `build-data.mjs`, a prototype of the deterministic migration, run against `.siftkit/runtime.sqlite`:

- Active nodes become entity notes. Owner aliases and nodes whose names match after normalization are merged.
- Active assertions become bullets under predicate headings.
- Pending and needs-confirmation candidates become `#unverified` bullets.
- Every active screenshot becomes a capture note. Captures still queued are tagged `#pending`.
- Chat sessions become chat notes, and each day gets a daily rollup.
- Facts recorded after the cutover appear as note-writer revisions.

Screenshot embeds are SVG placeholders. The real vault shows the PNG attachment. The SiftKit tidy-pass revision is scripted.

**The generated data contains real personal data. Do not commit `vault-data.js` without reviewing it.**
