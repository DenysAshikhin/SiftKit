Gates (in order)

Drain admission
  1. server not busy
  2. desktop heartbeat fresh
  3. no model call for 180 s
  4. mouse and keyboard idle ≥ 180 s
  5. battery and GPU minutes
Model work admissionWrites need the model loaded (the queue never loads it) and the resource budget. Captures need a vision-capable preset.
PreemptionInteractive work or an unload aborts the run. Nothing is written before the agent submits, so the job re-queues cleanly.

One capture, end to end

  1. The desktop app posts a screenshot; intake writes a pending capture note.
  2. vault_write capture is queued, or the capture waits for a vision model.
  3. After 3 idle minutes a drain runs the agent: it searches and reads the notes the screenshot touches, then submits edits.
  4. The applier writes them; the capture note gets its Learned section and its day is recorded.
  5. Follow-up vault_maintenance: retention, the daily note rebuild, then a review batch if nothing else is queued.
  6. The review agent checks plausibility, links and consistency, flags what is wrong and stamps the rest validated.

Validation loop

Access stampsChat retrieval and the agent's reads stamp notes and the values they show as accessed.
Queue orderEntity notes not validated in 30 days, least recently accessed first, then oldest validation, then oldest edit.
Review passFlags implausible facts and bad links with flag_doubt and contradictions with flag_conflict; deletes nothing.
Keep / DropIn the Review view. Keep on a doubt validates the value; Keep on a conflict replaces the old value; Drop removes the line.
