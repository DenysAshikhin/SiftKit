# Run c16a9829 follow-ups

Notes to address from orchestrator run `c16a9829` (rerun of the 67e089d0 task on the isolated approver, 2026-11-17). Each item becomes its own spec and plan when picked up.

## 1. Tests must never hit a real API or start a real service

**Rule.** No test, whether unit, process, or e2e, may:
- reach the real SiftKit status server (`127.0.0.1:4765`), the real engine (Tabby on `8098`), or any external network API;
- launch the real engine (TabbyAPI / exllamav3) or load a model onto the GPU;
- read or write the user's real runtime state: the repo-local `.siftkit/runtime.sqlite` of a real checkout, `~/.siftkit`, or the real config;
- terminate a process it did not spawn itself.

Engines, servers, and APIs are fakes the test owns: on leased ports, with temp runtime roots, cleaned up by the PIDs the test started. A test that would need the real thing is a live test, opt-in only, as the existing `test:live:*` scripts are.

**Incident.** At 20:47:01 local time, the orchestrator ran the testbed's process tests through `run_check`:

```
node .\src\test-runner\run-tests.ts --process orchestrator-run.e2e runtime-db-schema-orchestrator orchestrator-chat-sessions chat-overflow
```

At 20:47:19 the live Tabby serving the run exited with code 1. Engine run `70a292c4` has no traceback: its log stops after request `#643`, which finished at 20:47:01. Exit code 1 with no output matches a forced `taskkill /F`. The server reloaded the model on the next orchestrator request (20:48:16, ready 20:48:52), so about 1.5 minutes were lost. The test run itself exited 1, failing in `tests/fixtures/managed-engine-readiness-processes.test.ts` (used by `tests/process/run-tests-watchdog.test.ts`).

**Not yet proven.** Every kill found so far targets a PID the test spawned. Suspects to check first:
- `src/test-runner/run-tests.ts:62`: `terminateProcessTree(child.pid ?? 0)`, a tree kill of PID 0 when `child.pid` is undefined. The Toolhelp fallback in `src/lib/process-tree.ts` may walk descendants of PID 0.
- PID reuse: a tree kill of a PID recorded earlier that now belongs to another process.
- A process test or fixture that resolves the real server, engine port, or runtime root instead of its leased or temp ones.

**Findings (2026-11-18).**
- Reproduction: decoy `python.exe main.py` trees stood in for Tabby on `8098` and the server on `4765` while the process suite ran (all files but `chat-overflow`). No decoy was contacted or killed, so no test targets the live stack directly.
- PID 0 is not the cause: `terminateProcessTree` already rejects PIDs at or below 0.
- Root cause (most likely): Windows tree kills followed stale parent ids. Windows never clears a dead parent's id and reuses ids, and both `taskkill /T` and the Toolhelp walk matched children by parent id alone. A process whose parent had exited could therefore count as a descendant of a test process that reused that id, and be killed with `/F`, which exits with code 1 and no output, as the live Tabby did.

**Done.**
- `src/lib/process-tree.ts`: the snapshot carries each process's creation time, and a child counts only when it started no earlier than its parent; unreadable times count as not a child. `terminateProcessTree` no longer calls `taskkill /T`: it kills the verified descendants deepest first, then the root. Regression tests: `tests/process-tree.test.ts`, `tests/status-server-shutdown.test.ts`.
- `src/test-runner/live-instance-guard.ts`: every test process, including process-suite ones, fails on:
  - a request to a non-loopback host;
  - a child process whose command, arguments, or cwd name the real engine's `PythonPath` or TabbyAPI `WorkingDirectory`.

  These paths are now the constants `SIFT_DEFAULT_EXL3_PYTHON_PATH` and `SIFT_DEFAULT_EXL3_WORKING_DIRECTORY`, passed to the guard as `SIFTKIT_GUARD_ENGINE_PATHS`. Tests: `tests/process/live-instance-guard.test.ts`.
- Audit: the default, process, and dashboard suites pass under the stricter guard.

**Not covered.** A kill of an unrelated process whose id was reused between the snapshot and the kill, a window of milliseconds. A config whose engine paths differ from the defaults is guarded only by the ports and the runtime-database guard.

## 4. Dashboard chat sessions fail on `SparseDraftHead`

During the run, the server logged on every poll: `GET /dashboard/chat/sessions failed: Invalid SparseDraftHead 'undefined'; expected a non-negative integer (0 keeps the full draft head).` Some stored preset or session record has no `SparseDraftHead` (added in schema 91), and the reader rejects it instead of the schema upgrade filling it in.

## 5. Run b3c5c019: a worker wrote into the real repository (fixed 2026-11-18)

After a compaction, the orchestrator invented the absolute repo path `C:\Users\…\GitHub\siftkit` in a dispatch instruction. Its prompt never stated the real root. Worker `0616b37a` ran `cd` to that path, wrote its files there, and ran its tests there. `run` did not confine paths. The approver returned `unsure` (it did not know the root), and with `--approval off`, `unsure` runs the command. The stray files have been removed.

**Fixed:**
- `run` and `run_check` commands are refused before approval when they reach outside the repository root (absolute, UNC, home, or `..` paths, with `cd` followed) or when they cut a check's output with `Select-Object`, `Select-String`, `Out-File`, redirection, and similar. Workers had filtered 125 of 177 check commands despite the prompt rule. Code: `src/repo-search/engine/shell-command-policy.ts`.
- The orchestrator prompt and every child instruction state the absolute repository root. `dispatch` refuses an instruction that names an absolute path outside it.
- The approver sees the repository root. It denies writes, deletions, and directory changes outside the root, and approves the repository's own test, build, lint, and typecheck commands. Those commands had caused most of the 121 `unsure` verdicts.
- `record_review`:
  - accepts command evidence `{command}` for a check that passed (an attempt check, or a `run_check` since the latest child started);
  - shows the actual cited line when a snippet does not match;
  - names the valid criterion indexes when an index is unknown;
  - asks for one-line verbatim snippets.
- The test runner scopes `--process`/`--perf` name filters to that suite, and puts runner options before targets. Node ignored `--test-name-pattern` when it came after a file.

**Open:**
- The orchestrator's prompt cache is evicted by every worker run: 12 cold prefills of 100–220 s.
- A compaction keeps 8k of 180k tokens with no summary, so the orchestrator re-explores after each one.
- The orchestrator read a 173k-token prompt cold, then compacted two turns later.
